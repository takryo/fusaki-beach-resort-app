# 館内マップ 仕様(データスキーマ)

> **v3(精細版+ルート案内)**: 本ファイル末尾の「v3 拡張」を参照。
> 座標系は公式マップと同じ向き(海が上・横長)の viewBox 0 0 1800 640 に変更。


## 方針
- 公式マップ画像は同梱しない(著作権)。配置を参考にしたオリジナルの模式図SVGを描く
- データは `data/resort-map.js` に `window.RESORT_MAP = {...}` として定義
- 座標系: viewBox 0 0 1000 700(横長)。海(フサキビーチ)は左〜下側に配置

## スキーマ
```js
window.RESORT_MAP = {
  updatedAt: "2026-09-14",
  officialMapUrl: "https://...",   // 公式マップ(PDF/ページ)へのリンク
  // 背景の面(海・ビーチ・緑地・建物ブロック・道路)。描画順に並べる
  areas: [
    {
      id: "sea",
      kind: "sea" | "beach" | "green" | "building" | "pool" | "road" | "path",
      label: "フサキビーチ" | null,      // 面に直接書くラベル(任意)
      labelPos: { x: 120, y: 600 },      // ラベル位置(任意)
      // 多角形 or 矩形のどちらか
      points: "x1,y1 x2,y2 ..." | null,  // SVG polygon points
      rect: { x, y, w, h, r } | null     // 角丸矩形
    }
  ],
  // タップ可能な施設ピン。cat+name は data/resort-data.js の項目に一致させる
  pins: [
    {
      cat: "dining",              // resort-data.js のカテゴリid
      name: "ISHIGAKI BOLD KITCHEN",  // resort-data.js の項目名と完全一致
      short: "BOLD KITCHEN",      // マップ上の短い表示名
      icon: "🍽",
      x: 500, y: 300
    },
    // resort-data に対応項目がない場所(フロント、駐車場等)は cat: null で
    { cat: null, name: "フロント/ロビー", short: "フロント", icon: "🛎", x: 520, y: 280 }
  ]
};
```

## 品質基準
- 位置は公式マップに照らして「相対関係が正しい」こと(建物の並び・ビーチとの位置関係・
  ヴィレッジ/ヴィラエリアの区別)。縮尺の厳密さは不要
- ピンは重なって読めなくならないよう最低40px(座標単位)離す
- 全ピンの cat+name が resort-data.js と一致することを検証すること

# v3 拡張: 精細マップ+部屋からのルート案内

## 目的
- 公式ガイドマップ(202603_MAP_WEB.pdf)並みの建物粒度: 各ヴィラ棟・客室棟を個別の面として描く
- 「自分の部屋(部屋番号)」を設定すると、任意の施設までの徒歩ルートを園路に沿って表示

## 座標系(変更)
- viewBox **0 0 1800 640**。公式マップと同じ向き: **海・ビーチが上**、施設群が下、左が桟橋/サウス側、右がノースウイング/HIBANMUI側
- 公式マップの300dpi画像(4914x1750)からの変換: map_x = pdf_x * 1800/4914, map_y = pdf_y * 640/1750(ほぼ等倍アスペクト)

## RESORT_MAP v3 追加フィールド
```js
window.RESORT_MAP = {
  version: 3,
  updatedAt: "...",
  officialMapUrl: "...",
  metersPerUnit: 0.35,        // 距離換算(徒歩時間の目安計算用。おおよそで良い)
  areas: [...],                // 従来どおり(sea/beach/green/building/pool/road/path)
  pins: [...],                 // 従来どおり
  // ★新規: 客室棟。1棟=1エントリ。rooms で部屋番号レンジを持つ
  buildings: [
    {
      id: "gv-201",                 // 一意なid
      label: "V201-206",            // マップ上の表示(小さく)
      group: "ガーデンヴィラズ",      // 所属エリア名
      rect: {x,y,w,h,r} | points,   // 位置
      rooms: [{ prefix: "V", from: 201, to: 206 }],  // 複数レンジ可
      node: "n42"                   // 最寄りの経路ノードid
    }
  ],
  // ★新規: 経路ネットワーク(園路・通路のグラフ)
  nodes: [ { id: "n1", x: 100, y: 200 } ],
  edges: [ ["n1","n2"], ... ],      // 無向。距離は座標から自動計算
  // pins にも最寄りノードを追加: { ..., node: "n7" }
};
```

## 部屋番号の仕様(公式マップより)
- プレフィックス: S(サウスウイング)、V(ガーデンヴィラズ等ヴィラ系)、T(ガーデンテラス T101-T316)、N(ノースウイング)
- 入力は「V213」「v213」「213」いずれも受け付け、数字のみの場合は全プレフィックスから一意に決まれば採用、複数候補なら選択させる

## ルート案内の仕様
- ホーム/マップに「🏠 自分の部屋を設定」: 部屋番号入力 → 該当棟をハイライトし localStorage 保存(同期対象外)
- 設定済みなら、施設カード(マップ・リゾート一覧・予定の施設情報すべて)に「🚶 部屋からのルート」ボタン
- タップでマップ表示に切替え、Dijkstraで最短経路を計算し、太いアクセント色の線(丸端点・破線アニメ可)で描画。始点🏠と終点にマーカー。「徒歩約◯分(目安)」を表示(距離 × metersPerUnit ÷ 67m/分、1分未満は「すぐ」)
- ルート表示中は「案内を終了」ボタン。別施設を選ぶと引き直し
- 部屋未設定時はボタンの代わりに「部屋を設定するとルート表示できます」を1回だけ示唆

## 品質基準(v3)
- 建物・棟の相対配置と部屋番号レンジが公式マップと一致(全棟を突合リスト化して検証)
- グラフが連結(全ノードから全ノードへ到達可能)であることを機械検証
- ルートが建物・プールの面を横切らない(园路上のみ通る)ことを目視+サンプル機械検証
- 従来の面・ピン・フィルタ・ズーム品質基準は維持
